# Outage report: payment failures in Mobile Payments API

**Date:** 2026-07-22  |  **Severity:** SEV2  |  **Duration:** 42 minutes
**Customer impact:** approximately 47,194 failed or delayed payment transactions.

## Summary
Timeouts from the third-party LankaQR acquirer gateway gateway with no circuit breaker caused customers to see payment failures.

## Timeline
- T+0: Error rate on Mobile Payments API rose above 5%; on-call engineer paged automatically.
- T+10 min: Incident bridge opened; payments operations notified.
- T+21 min: Root cause identified.
- T+42 min: Service fully restored and backlog cleared.

## Root cause
LankaQR acquirer gateway experienced degraded performance and responded in 20-45 seconds instead of the usual 300 ms. Mobile Payments API had no circuit breaker or fallback for this dependency, so worker threads blocked and the failure spread to unrelated card transactions.

## Corrective and preventive actions
1. Manually disabled the LankaQR acquirer gateway route and queued transactions for retry.
2. Implement a circuit breaker with a 3-second timeout on all partner calls.
3. Agree an incident notification SLA with LankaQR acquirer gateway.

## Lessons learned
Detection worked, but prevention controls for this failure mode were missing or
not enforced. Follow-up actions are tracked in the reliability backlog.
