# Outage report: payment failures in Payment Switch

**Date:** 2026-08-08  |  **Severity:** SEV2  |  **Duration:** 55 minutes
**Customer impact:** approximately 26,067 failed or delayed payment transactions.

## Summary
Database connection pool exhaustion in Payment Switch under peak load caused customers to see payment failures.

## Timeline
- T+0: Error rate on Payment Switch rose above 5%; on-call engineer paged automatically.
- T+13 min: Incident bridge opened; payments operations notified.
- T+27 min: Root cause identified.
- T+55 min: Service fully restored and backlog cleared.

## Root cause
Payment Switch reached its maximum of 50 database connections during the salary-day peak. A slow reconciliation query held connections for up to 40 seconds, so new payment requests queued and timed out at the API gateway after 30 seconds.

## Corrective and preventive actions
1. Killed the long-running reconciliation query and moved it to the read replica.
2. Raise the pool limit to 120 and add a 5-second statement timeout for OLTP paths.
3. Add an alert when pool utilisation stays above 80% for 2 minutes.

## Lessons learned
Detection worked, but prevention controls for this failure mode were missing or
not enforced. Follow-up actions are tracked in the reliability backlog.
