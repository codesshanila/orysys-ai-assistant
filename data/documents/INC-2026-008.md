# Outage report: payment failures in Mobile Payments API

**Date:** 2026-05-23  |  **Severity:** SEV1  |  **Duration:** 96 minutes
**Customer impact:** approximately 16,135 failed or delayed payment transactions.

## Summary
Database connection pool exhaustion in Mobile Payments API under peak load caused customers to see payment failures.

## Timeline
- T+0: Error rate on Mobile Payments API rose above 5%; on-call engineer paged automatically.
- T+24 min: Incident bridge opened; payments operations notified.
- T+48 min: Root cause identified.
- T+96 min: Service fully restored and backlog cleared.

## Root cause
Mobile Payments API reached its maximum of 50 database connections during the month-end peak. A slow reconciliation query held connections for up to 40 seconds, so new payment requests queued and timed out at the API gateway after 30 seconds.

## Corrective and preventive actions
1. Killed the long-running reconciliation query and moved it to the read replica.
2. Raise the pool limit to 120 and add a 5-second statement timeout for OLTP paths.
3. Add an alert when pool utilisation stays above 80% for 2 minutes.

## Lessons learned
Detection worked, but prevention controls for this failure mode were missing or
not enforced. Follow-up actions are tracked in the reliability backlog.
