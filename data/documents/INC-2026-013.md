# Outage report: payment failures in Mobile Payments API

**Date:** 2026-09-26  |  **Severity:** SEV2  |  **Duration:** 27 minutes
**Customer impact:** approximately 38,370 failed or delayed payment transactions.

## Summary
Timeouts from the third-party SWIFT messaging hub gateway with no circuit breaker caused customers to see payment failures.

## Timeline
- T+0: Error rate on Mobile Payments API rose above 5%; on-call engineer paged automatically.
- T+6 min: Incident bridge opened; payments operations notified.
- T+13 min: Root cause identified.
- T+27 min: Service fully restored and backlog cleared.

## Root cause
SWIFT messaging hub experienced degraded performance and responded in 20-45 seconds instead of the usual 300 ms. Mobile Payments API had no circuit breaker or fallback for this dependency, so worker threads blocked and the failure spread to unrelated card transactions.

## Corrective and preventive actions
1. Manually disabled the SWIFT messaging hub route and queued transactions for retry.
2. Implement a circuit breaker with a 3-second timeout on all partner calls.
3. Agree an incident notification SLA with SWIFT messaging hub.

## Lessons learned
Detection worked, but prevention controls for this failure mode were missing or
not enforced. Follow-up actions are tracked in the reliability backlog.
