# Outage report: payment failures in Card Authorisation Service

**Date:** 2026-02-24  |  **Severity:** SEV1  |  **Duration:** 128 minutes
**Customer impact:** approximately 1,625 failed or delayed payment transactions.

## Summary
Configuration drift introduced by a manual production change to Card Authorisation Service caused customers to see payment failures.

## Timeline
- T+0: Error rate on Card Authorisation Service rose above 5%; on-call engineer paged automatically.
- T+32 min: Incident bridge opened; payments operations notified.
- T+64 min: Root cause identified.
- T+128 min: Service fully restored and backlog cleared.

## Root cause
A manual change to the Card Authorisation Service routing configuration was made directly in production to fix a minor issue, bypassing the change-approval pipeline. The next automated deployment overwrote part of the change, leaving an inconsistent routing table that rejected valid Friday evening transactions.

## Corrective and preventive actions
1. Restored the last known-good configuration from Git.
2. Block manual production changes; all config changes go through the pipeline.
3. Add a drift-detection job comparing live config with Git every 15 minutes.

## Lessons learned
Detection worked, but prevention controls for this failure mode were missing or
not enforced. Follow-up actions are tracked in the reliability backlog.
